# Power BI Build Guide — retail_bi_profitability.pbix

Click-by-click instructions for building the Power BI report on Windows from this
repo's star-schema CSVs. Budget about 45-60 minutes the first time.

> A `.pbix` file can only be created inside Power BI Desktop — it cannot be
> generated by a script on Linux/CI. This guide is the build script, in clicks.
> The final `.pbix` is listed in `.gitignore` on purpose (it is a large binary);
> the repo holds everything needed to rebuild it.

**Prerequisite:** Power BI Desktop installed (free, from the Microsoft Store or
microsoft.com). Run `python python/prep_and_verify.py` first so
`data/processed/` contains the five star-schema CSVs.

---

## Step 1 — Import the star schema

1. Open Power BI Desktop → **Get data → Text/CSV**.
2. Import these five files from `data\processed\` (repeat Get data for each):
   - `fact_sales.csv`
   - `dim_customer.csv`
   - `dim_product.csv`
   - `dim_date.csv`
   - `dim_region.csv`
3. For each file, check the preview: headers should be the snake_case column
   names from the repo. Click **Load** (not Transform) — the data is already clean.

## Step 2 — Create the relationships (Model view)

Open the **Model** view (third icon on the left rail). Drag these relationships
(all are one-to-many, dimension → fact, single direction):

| From (one side)              | To (many side)              |
|------------------------------|-----------------------------|
| dim_customer[customer_key]   | fact_sales[customer_key]    |
| dim_product[product_key]     | fact_sales[product_key]     |
| dim_region[region_key]       | fact_sales[region_key]      |
| dim_date[date_key]           | fact_sales[order_date_key] |

Notes:
- `fact_sales[ship_date_key]` stays unconnected on purpose: one active
  relationship per table pair keeps filter behaviour predictable. (Role-playing
  dimensions / USERELATIONSHIP is the advanced answer in interviews.)
- Hide every `*_key` column in the fact table and all key columns in the dims
  (right-click column → **Hide in report view**). Report users should only see
  descriptive fields and measures.

## Step 3 — Prepare dim_date for time intelligence

1. In `dim_date`, Power BI imports `full_date` as text. Select the column →
   **Column tools → Data type → Date**.
2. Right-click the `dim_date` table → **Mark as date table** → choose
   `full_date`. This is what the time-intelligence measures (YTD, YoY,
   SAMEPERIODLASTYEAR) rely on. The relationship to the fact table stays on
   the integer keys from Step 2 — filters still flow dimension → fact.
3. Sort `month_name` by `month`: select `month_name` → **Column tools →
   Sort by column → month**.

## Step 4 — Add the DAX measures

1. **Home → Enter data** → name the table `_Measures`, one column `x`, load it.
2. Right-click `_Measures` → **New measure**, and paste each measure from
   `powerbi/DAX_MEASURES.md` (Total Sales, Total Profit, Profit Margin %,
   Order Count, AOV, Avg Discount, Sales YTD, Sales PY, YoY Sales Growth %,
   Loss-Making Lines %, Deep-Discount Profit, Top Category Profit, …).
3. Set formats: currency measures → `$#,##0`; margin/growth → number, 2 decimals;
   Avg Discount → percentage.

## Step 5 — Page 1: Executive Overview

Rename the default page to **Executive Overview**. Canvas: 16:9.
Theme: **View → Themes → Executive** (or any dark-blue theme), keep it consistent.

Visuals:
1. **Card** — Total Sales (`$2,297,201` on full data).
2. **Card** — Total Profit (`$286,397`).
3. **Card** — Profit Margin % (`12.47`).
4. **Card** — Order Count (`5,009`) and **Card** — AOV (`$458.61`).
5. **Line chart** — Axis: `dim_date[year_month]`, Values: Total Sales +
   Sales Rolling 3M. (Sort axis by a hidden year+month — use
   `dim_date[year]` then `dim_date[month]` in the axis for correct order.)
6. **Clustered bar chart** — Axis: `dim_product[category]`, Values: Total Sales,
   second value: Total Profit (or a second chart for profit).
7. **Donut chart** — Legend: `dim_customer[segment]`, Values: Total Sales.
8. **Slicers** (left rail): `dim_date[year]`, `dim_region[region]`,
   `dim_product[category]`.

Formatting tips: turn on data labels on the bar chart; set the line chart's
Y-axis to currency with 0 decimals; give every card a title.

## Step 6 — Page 2: Profitability Deep-Dive

New page → rename **Profitability Deep-Dive**.

Visuals:
1. **Clustered bar chart (sorted ascending)** — Axis: `dim_product[sub_category]`,
   Values: Total Profit. Conditional formatting on bars: red when profit < 0
   (Format → Columns → Colors → fx → rule: if value < 0 then red).
   Tables (–$17,725) and Bookcases (–$3,473) should stand out at the bottom.
2. **Matrix** — Rows: `dim_product[category]` → `dim_product[sub_category]`,
   Values: Total Sales, Total Profit, Profit Margin %. Turn on conditional
   background colour for the margin column.
3. **Bar chart** — Top 10 products by profit: Axis `dim_product[product_name]`,
   Values Total Profit, Visual-level filter: Top N = 10 by Total Profit.
   (Canon imageCLASS 2200 Advanced Copier should be #1 at $25,200.)
4. **Bar chart** — Bottom 10 loss-makers: same setup, Bottom N = 10.
   (Cubify CubeX 3D Printer Double Head Print should be last at –$8,880.)
5. **Table** — Top customers: `dim_customer[customer_name]`, segment, Order
   Count, Total Sales, Total Profit, Profit Margin %. Point out that the #1
   customer by sales (Sean Miller, $25,043) is actually loss-making (–$1,981).
6. **Drill-through setup:** right-click the sub-category bar chart →
   add the product table page as a drill-through target: create a third page
   named **Product Detail**, set its Drill through filter to
   `dim_product[sub_category]`, add a table of products + a card for the
   filtered sub-category profit. Hide the Product Detail page.

## Step 7 — Page 3: Discount & Region Analysis

New page → rename **Discount & Region Analysis**.

Visuals:
1. **A discount-band helper column first** (Data view → fact_sales →
   New column):
   ```dax
   Discount Band =
   SWITCH (
       TRUE (),
       fact_sales[discount] = 0, "0%",
       fact_sales[discount] <= 0.10, "1-10%",
       fact_sales[discount] <= 0.20, "11-20%",
       fact_sales[discount] <= 0.30, "21-30%",
       fact_sales[discount] <= 0.50, "31-50%",
       "Over 50%"
   )
   ```
2. **Clustered column chart** — Axis: Discount Band, Values: Total Profit.
   The story in one visual: 0% band = +$320,988; anything above 20% is negative;
   Over-50% band = –$76,559 (–119.20% margin).
3. **Line + column combo** — Axis: Discount Band, Columns: Total Sales,
   Line: Profit Margin %. Shows margin falling off a cliff after 20%.
4. **Filled map or bar chart** — `dim_region[region]` vs Total Profit +
   Profit Margin %: West is best ($108,418 profit, 14.94% margin),
   Central is weakest on margin (7.92%).
5. **Scatter chart** — X: Avg Discount, Y: Profit Margin %, Details:
   `dim_product[sub_category]`, Size: Total Sales. Discounted furniture
   sub-categories cluster in the negative-margin corner.
6. **Card** — Deep-Discount Profit measure (–$135,376) as the page headline.

## Step 8 — Polish + save

1. **View → Page information** on page 1: add a description.
2. Add a text box title on each page ("Retail BI & Profitability Analysis").
3. Check every page with all slicers cleared — numbers must match
   `outputs/kpi_summary.json` exactly (Total Sales $2,297,200.86 etc.).
   If a number differs, a relationship or a measure is wrong — fix it before
   saving; the SQL outputs are the ground truth.
4. **File → Save As** → save into this repo folder as
   **`retail_bi_profitability.pbix`**.
5. Optional: **File → Export → Export to PDF** for a static copy to show in
   interviews when Power BI Desktop isn't available.
